## 7.2. Ключові покращення

### Largest Contentful Paint (LCP) — головний результат оптимізації

| Пристрій | До | Після | Коментар |
|----------|-----|-------|----------|
| **Mobile** | 2,4 с (близько до межі 2,5 с) | **1,1 с** | Суттєве покращення; запас до «поганого» порогу збільшився |
| **Desktop** | 0,7 с | **0,3 с** | Hero WebP + локальний хостинг замість picsum CDN |

**Причини покращення LCP (кроки 3–4):**
- Зображення **hero** переведено з `picsum.photos` на локальні **WebP** (`images/hero.webp`, −31% розміру).
- Той самий домен, що й HTML (GitHub Pages) — менше DNS/TLS до стороннього CDN.
- На hero **не** застосовано `loading="lazy"`, додано `fetchpriority="high"`.

### Показники без змін або з незначними коливаннями

- **Performance Score** — уже був на рівні 98–100; оптимізація не змінила бал (стеля Lighthouse).
- **CLS** — 0 до і після (`width`/`height` на зображеннях).
- **Mobile FCP** — 0,8 → 0,9 с (незначне коливання в межах похибки lab-тесту).
- **Mobile TBT** — 0 → 30 мс (залишається в зеленій зоні).

## 7.7. Висновок розділу 7

Повторне тестування PageSpeed Insights підтвердило ефективність технічної оптимізації: найбільш помітне покращення — **LCP** на Mobile (з 2,4 до 1,1 с) та Desktop (з 0,7 до 0,3 с). Загальні бали Performance залишились на високому рівні (98–100), оскільки до оптимізації сайт уже мав хороші lab-показники. Комплекс **WebP + локальні файли + lazy loading below fold** є найефективнішим заходом для цієї лабораторної. Для оцінки в реальних умовах потрібні польові дані GSC (Core Web Vitals report) після накопичення трафіку.
